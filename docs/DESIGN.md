# Design decisions

Each row is measured or sourced in `docs/research/` (01 proof pipeline + audit, 02 game design and
client, 03 WASM VM spike, 04 chunked execution spike). Changing a row is the orchestrator's call
and is recorded here with the date.

| # | decision | why / source |
|---|---|---|
| D1 | **Replay model.** `main(level: Array<felt252>, inputs: Array<felt252>) -> Array<felt252>` runs the level at 60 Hz with `num_solver_iterations = 4` (rapier golden-validated), shot cap 360 ticks, early stop on calm or all asleep, `level.shots` shots (1-5, default 3). Same code in three builds: proof (`main`, no prints), trace (`main_trace`, observer prints per-tick poses and game events), chunked (`init(level) -> state`, `step_chunk(state, inputs, k) -> state'`, on `rapier2d::WorldState`). | 02 §2; 04 |
| D2 | **Level encoding.** `Level { version: u16, level_id: u32, seed: felt252, gravity_y: Fixed, shots: u8, tick_cap: u16, bounds: (Fixed×4), sling_anchor: Vec2, pull_radius: u16, launch_scale: Fixed, projectiles: Array<u8>, materials: Array<Material>, bodies: Array<BodyDef> }`; `Material { density, friction, restitution: Fixed, hp: u32, force_threshold: Fixed, damage_per_impulse_dt: Fixed, score: u32 }`; `BodyDef { kind: u8 (0 static, 1 block, 2 core), shape: ShapeDef, pose: Pose2, material: u8 }` (`Pose2` / `Rot2` are rapier's, `rapier_math` via `rapier2d::prelude`: translation then rotation, felts `[x, y, re, im]`; amended 2026-09-25 after G2); `ShapeDef = Ball(Fixed) \| Cuboid(Fixed, Fixed) \| Polygon(Array<Vec2>) \| HalfSpace(Vec2)`. Felt layout = `Serde`; raw Q32.32 `i64` as felts (negative = `P - x`). `level_hash = poseidon_hash_span(felts)` computed inside the executable. JSON with decimal values is the editor's source of truth; felts are generated. Dynamic bodies are stored pre-settled and start asleep. | 02 §2.2 |
| D3 | **Inputs.** `Inputs { player: felt252, shots: Array<Shot> }`, `Shot { pull_x: i16, pull_y: i16, delay: u16 (≤ 60), ability_tick: u16 (0 = none; ignored in the MVP) }`; pull clamped to a disk of radius `pull_radius`: if `px² + py² ≤ R²` keep it, else `s = ceil_isqrt(px² + py²)` (ceiling integer square root, so the result provably stays inside the disk) and `px' = trunc(px·R / s)`, `py' = trunc(py·R / s)` (truncation toward zero; G6 implements it in `BigInt`, G3 must match it bit for bit; amended 2026-09-25 from "one `u128_sqrt`"); `v = -pull · launch_scale`. `inputs_hash = poseidon_hash_span(felts)`. `player` is proven so that a proof cannot be resubmitted by someone else. | 02 §1.1, §2.3 |
| D4 | **Outputs.** `[version, level_hash, seed, player, inputs_hash, score, won, shots_used, ticks_run, final_state_hash]` (10 felts). `final_state_hash` = Poseidon of the raw poses of the remaining dynamic bodies. | 02 §2.4 |
| D5 | **End of shot.** (1) all dynamic bodies asleep, or (2) calm: every awake dynamic body has `\|v\|² < ε_v²` and `ω² < ε_ω²` (0.05 m/s, 0.05 rad/s, fused dot, no sqrt) for 20 consecutive ticks, then `sleep()` on all, or (3) the cap; then the pebble is removed. Out-of-bounds bodies are removed at once, the pebble included (a core counts as destroyed). **Spent pebble (amended 2026-09-25 after G3b):** a rolling ball never calms (no rolling resistance, as upstream). G3b measured damping: 0.5 / 2.0 still ends 3 of 6 shots on the cap and 1.0 / 4.0 ends them all but shortens the flight so much that the reference pull no longer reaches the pile and the client's exact arc becomes wrong. Decision: **no damping**; the pebble is excluded from the calm test once it has touched a **block or core** (contacts with static colliders such as the ground do not count, so a pebble landing short can still roll into the pile) or after `PEBBLE_FLIGHT_CAP` ticks (120) since launch; when every other dynamic body is calm for 20 ticks (or asleep), the pebble is removed and the shot ends. Flight stays exact against `client/src/aim/arc.ts`. **Settle step:** `GameTrait::new` runs one `dt = 0` step then sleeps every dynamic body, because rapier2d alpha.1 wakes the parent of every freshly inserted collider (escalated). | 02 §2.5; G3 |
| D6 | **Damage.** After each `step_with_force_events`, for each event and each non-static non-pebble side: `excess = total_force_magnitude - material.force_threshold`; if `> 0`, `hp -= floor(excess · damage_per_impulse_dt)`; removals at the end of the tick in ascending handle order. Each collider's `contact_force_event_threshold` = its material threshold. One `Fixed` mul per event side, no sqrt. | 02 §3 |
| D7 | **Scoring and win.** Block destroyed: material score (timber 50, frost 100, slate 150); core 1 000; unused shot when won 2 000; `u32`. Win = all cores destroyed, checked after each tick; the level stops at the end of that shot. | 02 §1.1 |
| D8 | **Client.** The Cairo replay itself runs in the browser: `executable.json` on lambdaclass cairo-vm 3.2 compiled to wasm32 in a Web Worker (no fork; a ~300-line runner handles the executable-wrapper hints and captures `println!`), **chunked** (state in, K ticks, state out; step-budgeted chunks of 2-5M steps, VM memory segment pre-reserved at **1.25x** the previous chunk's cells per tick, measured by G1c: 1.1x overruns after the impact and doubles the peak to 556 MB; first chunk K = 5, then K = floor(3.5M / previous steps per tick) clamped to [1, 60]), one persistent warmed-up worker. Renderer: Vite + TypeScript + PixiJS v8; poses converted to `f64` only for drawing; exact BigInt flight preview until first contact. Measured (G1b in Firefox, G1c in Node on the loaded VPS): 2.5-3.7M steps/s, 330-410 MB per chunk, first tick in 0.2-0.3 s; a 4e7-step shot = 12-14 s. cairo-vm is a git dependency pinned to `f7ac327f` plus a 16-line reservation patch applied by `client/vm/scripts/vendor.sh` (follow-up: upstream it or a `bal7hazar/cairo-vm` branch). | 03, 04 |
| D9 | **Proof and contract.** Target: SNIP-36 in-protocol verification (Sepolia first: the 1.1B-gas large-proof support reaches mainnet on 2026-10-05 pending governance). The level logic is a contract entry point `simulate(level_hash, inputs)` executed in the virtual OS, emitting the outputs as an L2→L1 message; `submit(raw_message)` checks `proof_facts` (virtual-OS program hash, message hash), `player == caller`, the nullifier `poseidon(level_hash, player, inputs_hash)`, then records the best record (`(won, score)` lexicographic; leaderboard of won records only, top 10) and emits `LevelValidated`. Provisional SNIP-36 facts layout (G7, to be confirmed by E2): program hash at index 0, message hash `poseidon([from, to, len, ...payload])` with `to = 'SLINGFALL'`. `proof_facts` exists in Cairo 2.19.4 (`TxInfo.proof_facts`) and snforge 0.61 can cheat it. Fallback: Stone + Herodotus Integrity (Atlantic) with `fact = poseidon(PROGRAM_HASH, output_hash)`. `scarb prove` of the executable is a development tool only. Full inputs go in calldata. Wallet: Cartridge Controller first, get-starknet fallback. | 01, 01b |
| D10 | **Budget.** ≤ **3e7 Cairo steps per shot** (target; 8-10 blocks + 2-3 cores), revised by measurements; 1.1B L2 gas per proven transaction (≈ 9M steps) is the on-chain unit, so a shot may span several chunked transactions until rapier's BT wave lowers the per-tick cost (pile12 today: 333k steps per tick average, 540k during impact). | 01 §5, 04 |
| D11 | **Dependencies.** `rapier2d` (and `fixed`, `glam`) by registry version only, pre-releases pinned exactly (`rapier2d = "0.1.0-alpha.1"` since 2026-09-25); a bump is its own PR with the golden fixtures regenerated. No vendoring, no git revs. Missing engine API = escalation to the programme session. | owner's rule; pm decisions 2026-09-25 |
| D12 | **Vocabulary (working).** Game: Slingfall. Projectile: pebble (ball r = 0.25 m, density 4, friction 0.5, restitution 0.2). Materials: timber (1 / 0.6 / 0.1 / hp 100 / 40 N / toughness 1), slate (2.5 / 0.8 / 0.05 / 300 / 120 N / 3), frost (0.9 / 0.05 / 0.2 / 40 / 15 N / 0.5), all to be tuned in G8. Targets: cores (hp 30, threshold 10 N). | 02 §1.1 |
