# Design decisions

Each row is measured or sourced in `docs/research/` (01 proof pipeline + audit, 02 game design and
client, 03 WASM VM spike, 04 chunked execution spike). Changing a row is the orchestrator's call
and is recorded here with the date.

| # | decision | why / source |
|---|---|---|
| D1 | **Replay model.** `main(level: Array<felt252>, inputs: Array<felt252>) -> Array<felt252>` runs the level at 60 Hz with `num_solver_iterations = 4` (rapier golden-validated), shot cap 360 ticks, early stop on calm or all asleep, `level.shots` shots (1-5, default 3). Same code in three builds: proof (`main`, no prints), trace (`main_trace`, observer prints per-tick poses and game events), chunked (`init(level) -> state`, `step_chunk(state, inputs, k) -> state'`, on `rapier2d::WorldState`). | 02 §2; 04 |
| D2 | **Level encoding.** `Level { version: u16, level_id: u32, seed: felt252, gravity_y: Fixed, shots: u8, tick_cap: u16, bounds: (Fixed×4), sling_anchor: Vec2, pull_radius: u16, launch_scale: Fixed, projectiles: Array<u8>, materials: Array<Material>, bodies: Array<BodyDef> }`; `Material { density, friction, restitution: Fixed, hp: u32, force_threshold: Fixed, damage_per_impulse_dt: Fixed, score: u32 }`; `BodyDef { kind: u8 (0 static, 1 block, 2 core), shape: ShapeDef, pose: Pose2, material: u8 }`; `ShapeDef = Ball(Fixed) \| Cuboid(Fixed, Fixed) \| Polygon(Array<Vec2>) \| HalfSpace(Vec2)`. Felt layout = `Serde`; raw Q32.32 `i64` as felts (negative = `P - x`). `level_hash = poseidon_hash_span(felts)` computed inside the executable. JSON with decimal values is the editor's source of truth; felts are generated. Dynamic bodies are stored pre-settled and start asleep. | 02 §2.2 |
| D3 | **Inputs.** `Inputs { player: felt252, shots: Array<Shot> }`, `Shot { pull_x: i16, pull_y: i16, delay: u16 (≤ 60), ability_tick: u16 (0 = none; ignored in the MVP) }`; pull clamped to a disk of radius `pull_radius` (integer compare, one `u128_sqrt` + one division per shot when clamping); `v = -pull · launch_scale`. `inputs_hash = poseidon_hash_span(felts)`. `player` is proven so that a proof cannot be resubmitted by someone else. | 02 §1.1, §2.3 |
| D4 | **Outputs.** `[version, level_hash, seed, player, inputs_hash, score, won, shots_used, ticks_run, final_state_hash]` (10 felts). `final_state_hash` = Poseidon of the raw poses of the remaining dynamic bodies. | 02 §2.4 |
| D5 | **End of shot.** (1) all dynamic bodies asleep, or (2) calm: every awake dynamic body has `\|v\|² < ε_v²` and `ω² < ε_ω²` (0.05 m/s, 0.05 rad/s, fused dot, no sqrt) for 20 consecutive ticks, then `sleep()` on all, or (3) the cap; then the pebble is removed. Out-of-bounds bodies are removed (a core counts as destroyed). | 02 §2.5 |
| D6 | **Damage.** After each `step_with_force_events`, for each event and each non-static non-pebble side: `excess = total_force_magnitude - material.force_threshold`; if `> 0`, `hp -= floor(excess · damage_per_impulse_dt)`; removals at the end of the tick in ascending handle order. Each collider's `contact_force_event_threshold` = its material threshold. One `Fixed` mul per event side, no sqrt. | 02 §3 |
| D7 | **Scoring and win.** Block destroyed: material score (timber 50, frost 100, slate 150); core 1 000; unused shot when won 2 000; `u32`. Win = all cores destroyed, checked after each tick; the level stops at the end of that shot. | 02 §1.1 |
| D8 | **Client.** The Cairo replay itself runs in the browser: `executable.json` on lambdaclass cairo-vm 3.2 compiled to wasm32 in a Web Worker (no fork; a ~300-line runner handles the executable-wrapper hints and captures `println!`), **chunked** (state in, K ticks, state out; step-budgeted chunks of 2-5M steps, VM memory segment pre-reserved from the previous chunk's cells), one persistent warmed-up worker. Renderer: Vite + TypeScript + PixiJS v8; poses converted to `f64` only for drawing; exact BigInt flight preview until first contact. Measured: 2.5-3.4M steps/s in Firefox, 300-410 MB per chunk, first tick in 0.2-0.3 s; a 4e7-step shot = 12-14 s on the loaded VPS. | 03, 04 |
| D9 | **Proof and contract.** Target: SNIP-36 in-protocol verification (Sepolia first: the 1.1B-gas large-proof support reaches mainnet on 2026-10-05 pending governance). The level logic is a contract entry point `simulate(level_hash, inputs)` executed in the virtual OS, emitting the outputs as an L2→L1 message; `submit(raw_message)` checks `proof_facts` (virtual-OS program hash, message hash), `player == caller`, the nullifier `poseidon(level_hash, player, inputs_hash)`, then records best score / won and emits `LevelValidated`. Fallback: Stone + Herodotus Integrity (Atlantic) with `fact = poseidon(PROGRAM_HASH, output_hash)`. `scarb prove` of the executable is a development tool only. Full inputs go in calldata. Wallet: Cartridge Controller first, get-starknet fallback. | 01, 01b |
| D10 | **Budget.** ≤ **3e7 Cairo steps per shot** (target; 8-10 blocks + 2-3 cores), revised by measurements; 1.1B L2 gas per proven transaction (≈ 9M steps) is the on-chain unit, so a shot may span several chunked transactions until rapier's BT wave lowers the per-tick cost (pile12 today: 333k steps per tick average, 540k during impact). | 01 §5, 04 |
| D11 | **Dependencies.** `rapier2d` (and `fixed`, `glam`) by registry version only, pre-releases pinned exactly (`rapier2d = "=0.1.0-alpha.N"`); a bump is its own PR with the golden fixtures regenerated. No vendoring, no git revs. Missing engine API = escalation to the programme session. | owner's rule; pm decisions 2026-09-25 |
| D12 | **Vocabulary (working).** Game: Slingfall. Projectile: pebble (ball r = 0.25 m, density 4, friction 0.5, restitution 0.2). Materials: timber (1 / 0.6 / 0.1 / hp 100 / 40 N / toughness 1), slate (2.5 / 0.8 / 0.05 / 300 / 120 N / 3), frost (0.9 / 0.05 / 0.2 / 40 / 15 N / 0.5), all to be tuned in G8. Targets: cores (hp 30, threshold 10 N). | 02 §1.1 |
