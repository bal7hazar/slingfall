# slingfall_game

The level logic of Slingfall as a library (`docs/DESIGN.md` D1, lot G4b): the code that the proof
build, the trace build, the chunked build and the contract's `simulate` all run. In the root
workspace, gas-enabled, tested with `snforge test -p slingfall_game`; the executables
(`enable-gas = false`) are in the nested `crates/slingfall_replay` package, which depends on this
crate by path. No `starknet` dependency.

| module | contents |
|---|---|
| `play` | `play(level, inputs, ref obs) -> Outputs`; `step_shot` (one shot with a tick budget), `ShotProgress`; `Observer<O>`, `NoopObserver`; `level_over`, `outputs`, `decode` |
| `chunk` | `ChunkState` (7-felt header, level, `GameState`), `init_state`, `step_state`, `state_outputs`, `CHUNK_STATE_VERSION`: what `init` / `step_chunk` run |
| `errors` | the `replay: *` panic messages (stable API) |
| `fixtures` | the pile10 reference shot and its golden outputs, for the tests of this crate, of `slingfall_replay` and of the contract |

Fixture levels: `slingfall_level::level::fixtures` (generated by `tools/levelc/levelc.py to-cairo`).
The proof build's cost is the rules' cost (`play` + `NoopObserver` on the pile10 reference shot:
32,133,817 snforge steps, `steps/slingfall_game/play.snap`); see `crates/slingfall_replay/README.md`
for the executables, the trace lines and the step tables.
